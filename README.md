# 义乌选品台

给义乌市场采购公司用的外贸选品工作台。业务员在这里做两件事：客户来了，按目标市场和需求从目录里排出可推的货；没客户时，按行情主动挑一批这周值得发的新品。

这不是工厂决定「要不要做独立站」的工具。独立站提纲只放在侧栏后面，买家以后明确要站点时再打开。

公司显示名默认是「义乌选品台」，在设置里改成你们自己的名字。不要把它写成某个官方品牌。

## 本地运行

需要 Node.js 20 或以上。

```bash
npm install
npm run dev
```

浏览器打开 [http://127.0.0.1:3847](http://127.0.0.1:3847)。

生产构建：

```bash
npm run build
npm start
```

本地 `npm start` 默认端口 3847。如果环境里有 `PORT`，会改用那个端口。

不需要数据库，也不需要 API 密钥。录入的询盘、粘贴的词表、笔记和设置都在这台浏览器的 localStorage 里。设置页可以「恢复示例并清空录入」。

## 部署到 Vercel

这是标准 Next.js 应用，不是纯静态导出。数据工位的两个状态接口（`/api/stubs/keyword-metrics`、`/api/stubs/serp`）要跟着服务一起部署，所以不要设 `output: 'export'`。

不需要任何环境变量。留空即可。即使以后有人在 Vercel 里填写 `DATAFORSEO_LOGIN`，当前版本也不会向外请求，也不会扣费。

1. 在 [Vercel](https://vercel.com/new) 导入这个仓库。
2. Framework Preset 选 **Next.js**。Install Command 用 `npm install`，Build Command 用 `npm run build`。不要改 Output Directory，也不要加自定义 Start Command。
3. Environment Variables 留空，直接 Deploy。

部署完成后，打开 Vercel 给出的地址即可。示例目录会直接出现，不依赖外部服务。

## 业务员怎么用

**按需推荐。** 客户说了国家、类目、价带、起订、想要的认证和一段原话。填进表单，看匹配分、理由、风险和未知项，复制一段中英话术再发出去。结果可以存成案例。

**行情推新。** 先选市场和类目。看「本周值得发」「示例趋势向上」「季节窗口」「新品窗口」。话术里不要写成市场已经验证，只写成「义乌有类似货，问对方要不要看样」。

两条线都可以点进单品，看意图分组、竞争阅读、需核实的认证清单，再放进一页报告，用浏览器打印成 PDF。

## 什么是示例，什么不是

目录里的搜索量、CPC、难度、趋势、竞争结构、价格、起订和交期，全部是**示例数据**，用来把流程跑通，不代表真实行情。进口额没有填，因为没有海关摘录，页面上保持未知。

| 标记 | 含义 |
| --- | --- |
| 示例 | 预置目录或内部示例口径，不是工具导出 |
| 实测 | 你在数据工位或单品页粘贴的关键字规划师、Google Trends 或当次搜索结果 |
| 未知 | 还没贴、或这个市场不在主推清单里，不用 0 冒充 |
| 假设 | 询盘粗算和汇率。默认是「月搜索量 × 8% 点击份额 × 2% 询盘率」，公式写在页面上，比率在设置里改 |
| 需核实 | 认证、税号、宣称。勾选只表示你问过工厂，不是系统确认已获证 |

Google Trends 的数字会记成相对热度，不会被写成月搜索量。关键字规划师的页首出价是广告出价区间，不是账户实际花费。

第一次打开会带一个「美国节日搞怪小礼品」的示例案例，方便看推荐长什么样。那不是真实客户。

## 目录

五个类目各 10 个起步单品：3C 数码、大健康、家居、儿童玩具、搞怪趣味。市场可以在美国、英国、德国、澳大利亚、中东、日本之间切换。非主推市场不生成示例搜索量。

## 数据工位

把关键字规划师或 Trends 的表贴进去，列名认中英文表头。对得上英文品名的词会挂到单品上，单品页里实测会盖住对应格子，旁边仍能看出来源。

`/api/stubs/keyword-metrics` 和 `/api/stubs/serp` 只返回「未外呼、不扣费」。即使本机有 `DATAFORSEO_LOGIN`，当前版本也不会去请求数据商。示例见 `.env.example`。
